CHOO-CHOO CHARLES v0.6.0 ALPHA - LOCAL VALIDATION
================================================

PERFORMANCE REGRESSIONS
----------------------
PASS: 1,200 consecutive simulated 50 ms maintenance callbacks after initial
  gameplay binding (60 nominal seconds) execute 60 native ownership checks,
  zero native enable calls, zero global actor/controller searches, and zero
  full automatic reflection snapshots. The guard remains armed and ready.
PASS: core's six Charles field patches share at most one Charles full-name
  read per maintenance pass. The address-plus-path ownership identity remains
  unchanged; caches are replaced for each maintenance/discovery pass.
PASS: the dedicated 16 ms heat loop still clears exact counters and jam latches.
  The 50 ms loop does not duplicate it during stable play; newly bound trains
  get immediate cooling and the 50 ms fallback remains available.
PASS: damage callbacks retain core protection but do not invoke native entry
  mutation, deep reflection, HUD work or routine file I/O inline.
PASS: changing the viewport world bypasses the retained controller, rejects
  previous-world actors, restores the guard when no player is present and
  reactivates protection/cooling when gameplay returns.
PASS: the logger batches 1,000 ordered records into one file write batch, with
  no write-file opens before flush. Binary append keeps Windows byte caps
  independent of text-mode newline expansion.

These are measured call counts at simulated engine boundaries, not game FPS
measurements. No claim of a specific FPS increase is made.

LIMITS / USER CONFIRMATION
-------------------------
The user confirmed v0.5 No Overheat and survival after an enemy shot. Their
latest supplied report records NightmareMode=true during player damage events.
The earlier Classic baseline was also user-confirmed. v0.6 preserves these
mechanisms while changing housekeeping and diagnostic work.

This environment does not run Choo-Choo Charles or Windows. Engine/native DLL
boundaries are mocked in Lua tests; the actual portable native core and Lua C
bridge are tested separately. PowerShell tests exercise real scripts on Linux,
using temporary fake installations and fixture-only process/backup overrides.
The v0.6 update still needs a live frame-pacing check on the user's PC.
The report contained no frame timings, so exact causal shares are not known.

A train-health decrease with F7 ON remains documented in TECHNICAL_NOTES.txt.
This performance update does not expand the set of train-damage paths covered.
