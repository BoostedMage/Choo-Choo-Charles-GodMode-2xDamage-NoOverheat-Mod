Implementation boundaries
-------------------------
Core only writes observed exact damage fields, actual player varHealthMain for
bounded nonlethal recovery, and native bCanBeDamaged. It never guesses a train HP
write target, modifies save files directly, edits PAK files, globally clears
Charles.Can Damage, changes NightmareMode, or suppresses the story guide death.

All UObject work is scheduled on the game thread. Controller/local world/class
checks and actor references select live targets; menu/default objects are excluded.
NotifyOnNewObject requests a rescan. BeginPlay and a 50 ms game-thread loop apply
fields after initialization. A legacy LoopAsync path queues onto the game thread.

Native ApplyDamage/ApplyPointDamage PRE hooks zero BaseDamage only for the bound,
enabled player or locomotive. They do not modify outgoing damage, preventing
stacking with the Charles hit multipliers. Standard radial damage is handled only
by native damageability, not a broad zero-radius-damage hook that could also
disable player explosions.

Blueprint Damage hooks are POST observers. They log, check for gaps and perform
bounded nonlethal recovery. They do not cancel the original Blueprint function.
No unsupported Lua pre-Blueprint API, invented C++ cancellation function, raw
memory offset or unvalidated bytecode patch is shipped.

Captured per-instance baselines restore on OFF. Failed restorations remain
pending and retry; HUD says OFF (RESTORING). Old live actors are restored on
rebind. Each doubled field is compared to the last applied value to avoid
compounding on poll. A game replacement value is treated as a fresh baseline;
relative phase scaling of an already patched value remains unverified.

Readback readiness is deliberately separate from enable intent. A detected
health loss clears readiness for that actor for the session, even if recovered.
Initial zero health before first positive health is treated as initialization,
not a permanent breach. Dead/zero-health actors are not resurrected.

Known unresolved requirements
-----------------------------
The requested universal player/train invulnerability and 2x damage for every
weapon, opening event, boss phase and both difficulties are NOT established by
these offline tests. Direct scripted death, direct HP assignment, and sources
outside the verified Charles fields may bypass protection. Field application
after BeginPlay/50 ms polling does not guarantee first-frame protection.

The train's true health storage and its damage function parameter semantics
still need the expanded live report. Metadata names alone cannot demonstrate
execution order. UE4SS normally lacks FProperty:GetPropertyFlags in Lua, so the
collector marks unclassified function fields explicitly rather than presenting
locals as parameters. Positional event values are logged without invented names.

Do not hot reload this Lua mod. Restart the game between updates so captured
baselines correspond to a fresh unmodified process. UE4SS OnUnload is not used
as an assumed safe game-thread restoration point.

Validation performed
--------------------
Actual Lua 5.4 loaded/compiled all four production modules. Isolated Lua tests
exercise controls, state, reflection and property mutation against values from
the supplied report, plus failure/scene-change cases. Tests include:
  - plain two-argument RegisterKeyBind calls, actual F6/F7/F8 label changes;
  - F11 visibility independent of gameplay flags; F9 while hidden;
  - native target parameter writes and unrelated actors left unchanged;
  - menu actor exclusion, live world selection and exact class paths;
  - 2x stability across repeated polls and toggles, baseline restoration;
  - independent train/player sources and native flags;
  - transient restoration failure retained/retried;
  - original unused varHealth remains untouched;
  - bounded recovery, explicit protection-gap status, no death resurrection;
  - field 291 and false booleans survive full reflection;
  - component/struct expansion, explicit limits and exact spaced names;
  - HUD cleanup on controller/world replacement and failed creation.

Verification scripts are included in Verification/. See VALIDATION_RESULTS.txt
for the final test execution result. Mocks verify our Lua logic and API wiring;
they cannot prove the game's Blueprint execution, live UMG rendering, weapon
damage totals or Nightmare behavior. No in-game test was performed here.

Installer invariants
--------------------
Existing UE4SS only. Stages outside Mods; replaces only this mod folder and its
mods.txt entry. Preserves unrelated entry text/encoding/newlines. Local backups
and failure rollback retain original mod/config. The log collector has explicit
bounds and omission manifest; it does not upload saves or other mod folders.
